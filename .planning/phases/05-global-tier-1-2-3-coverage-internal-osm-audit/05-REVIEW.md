### HI-01: `run_price_fetch()` silently corrupts curated `petrol_95` (and 5 derived grades) across 150+ Tier 3 territories on every online fetch [HIGH / BLOCKER]

**File:** `src/ets2v2/fetch/pipeline.py:196-225, 591-628` (D-10, D-11)
**Issue:** `data/curated/tier3_fuel_baselines.json` stores independent, clean-room curated EUR/L prices for **both** `diesel_eur_per_liter` and `petrol_95_eur_per_liter` (e.g., `IR`: `0.010` / `0.025`, `VE`: `0.010` / `0.035`, `BN`: `0.215` / `0.368`, `CG`: `0.760` / `1.180`, `US`: `0.920` / `0.800`, `CA`: `1.120` / `1.080`). `seed_initial_lockfile()` (`normalize/lockfile.py:270-285`) seeds both anchors accurately.

However, during every online `ets2v2 fetch` run, `pipeline.py:592-601` (and `618-627` for fresh lockfiles) reprices all retained seeded/Tier 3 territories through `_build_baseline_entry()` (`pipeline.py:196-225`), which takes only `diesel_eur` and unconditionally overwrites `petrol_95` with `diesel_eur_3dp * 1.03`:
```python
diesel_eur_3dp = round_eur_per_liter(diesel_eur)
petrol_95_eur_3dp = round_eur_per_liter(diesel_eur_3dp * _SEED_PETROL_TO_DIESEL_RATIO)
```
**Directly reproduced:** Running `run_price_fetch()` against a copy of `state/prices.lock.json` with unchanged FX rates silently altered `petrol_95` across **150 out of 186** curated territories:
- `IR`: `petrol_95` dropped **-60%** (`1137.5 -> 455.0 IRR/L`, collapsing to floor-clamped diesel `0.010 EUR/L`)
- `VE`: `petrol_95` dropped **-71%** (`1.925 -> 0.55 VES/L`)
- `BN`: `petrol_95` dropped **-40%** (`0.5299 -> 0.3182 BND/L`)
- `CG`: `petrol_95` dropped **-34%** (`774.0293 -> 513.6143 XAF/L`)
- `CO`: `petrol_95` dropped **-28%** (`4232.0 -> 3031.4 COP/L`)
- `US` (when `EIA_API_KEY` unset) and `CA`: inverted petrol from cheaper-than-diesel (`0.864` / `1.62`) to more-expensive-than-diesel (`1.0238` / `1.731`).

Because `compute_secondary_grade_prices()` derives `petrol_98`, `petrol_100`, `petrol_92`, `e85`, and `lpg` from `petrol_95`, all 6 petrol/LPG grades are corrupted simultaneously.         round_eur_per_liter(petrol_95_eur)
        if petrol_95_eur is not None
        else round_eur_per_liter(diesel_eur_3dp * _SEED_PETROL_TO_DIESEL_RATIO)
    )

### HI-02: `validate_ooxml_zip_safety()` leaves `zlib.error` uncaught (breaking circuit breakers & crashing CI) and misses UTF-16 `<!DOCTYPE`/`<!ENTITY` XML payloads [HIGH / BLOCKER]

**File:** `src/ets2v2/fetch/_parsing.py:113-154`, `src/ets2v2/fetch/ec_bulletin.py:349-358`, `src/ets2v2/fetch/global_tier1.py:1359-1368`, `src/ets2v2/fetch/tier2_portals.py:265-283` (T-05-07, T-05-11, D-07)
**Issue:** Two concrete defects affect the shared OOXML safety boundary used by EC WOB, JP METI, RU Rosstat, ZA DMRE/CEF, and NG NBS:
1. **Circuit-breaker bypass & Friday CI crash on corrupt deflate streams (reproduced):** `validate_ooxml_zip_safety()` only catches `zipfile.BadZipFile` (`line 153`). When `member.read(...)` (`line 140`) encounters a corrupted deflate block (e.g., invalid block type `0x06`), Python's `zlib` raises `zlib.error` — which does **not** inherit from `ValueError`, `OSError`, or `zipfile.BadZipFile`. None of `validate_ooxml_zip_safety()`, `_run_tier2_guarded()`, `fetch_jp_meti()`, or `fetch_ec_weekly_oil_bulletin()` catch `zlib.error` (or `RuntimeError` from `zipfile`), so a single corrupted `.xlsx` on a Tier 2 national portal bypasses `_run_tier2_guarded()` and crashes the entire Friday `ets2v2 fetch` CI job.
2. **UTF-16 `<!DOCTYPE`/`<!ENTITY` XXE guard bypass (reproduced):** Line 149 matches raw member bytes against ASCII-only `_XML_FORBIDDEN_DECL_BYTES_RE = re.compile(rb"<!(?:DOCTYPE|ENTITY)\b", flags=re.IGNORECASE)`. XML 1.0 permits UTF-16LE/BE encoding (which Expat and `openpyxl` parse natively). A valid `.xlsx` whose `xl/workbook.xml` contains `<?xml version="1.0" encoding="UTF-16"?><!DOCTYPE foo [<!ENTITY x "hello">]><workbook/>` encoded in UTF-16 **passes `validate_ooxml_zip_safety()` silently** and loads cleanly in `openpyxl.load_workbook(..., read_only=True, data_only=True)`. Additionally, XML parts without `.xml`/`.rels` suffixes (referenced via `.rels`) skip the check entirely.

**Fix:**
- Catch `(zipfile.BadZipFile, zlib.error, RuntimeError, EOFError)` in `validate_ooxml_zip_safety()` and convert them to `ValueError(f"Invalid or corrupt OOXML ZIP archive: {exc}")`.
- Detect UTF-16LE/UTF-16BE BOMs (`b"\xff\xfe"`, `b"\xfe\xff"`) and null-interleaved `<` (`b"<\x00"`, `b"\x00<"`) in `validate_ooxml_zip_safety()`, decoding candidate XML/rels members (or any XML-looking member) to `str` before checking `<!(?:DOCTYPE|ENTITY)\b` (or checking both UTF-8 and UTF-16 patterns):
```python
def _contains_forbidden_xml_decl(data: bytes) -> bool:
    if _XML_FORBIDDEN_DECL_BYTES_RE.search(data):
        return True
    if data.startswith((b"\xff\xfe", b"\xfe\xff")) or b"\x00" in data[:64]:
        for enc in ("utf-16", "utf-16-le", "utf-16-be"):
            try:
                decoded = data.decode(enc)
            except UnicodeDecodeError:
                continue
            if _XML_FORBIDDEN_DECL_TEXT_RE.search(decoded):
                return True
    return False
```
Add negative regression tests in `tests/test_fetch_global_tier1.py` and `tests/test_fetch_tier2_portals.py` for both a corrupt deflate stream (`zlib.error`) and a UTF-16-encoded `<!DOCTYPE`/`<!ENTITY` workbook.
